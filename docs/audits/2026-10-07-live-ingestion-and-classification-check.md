## Why document arrivals stalled

Active fetch-worker settings and counters:

| Limit / counter | Observed |
|---|---:|
| Live article fetch limit | 300/day |
| Live fetch stages counted today | 300 |
| Historical PDF fetch limit | 25/day |
| Historical report fetches counted today | 25 |
| Live artifact bytes recorded today | 261,923,153 (~249.8 MiB) |
| Live artifact byte allowance | 256 MiB/day |
| Extra reserve checked before a PDF fetch | 25 MiB |
| Free volume space | 118,372,765,696 bytes (~110.2 GiB) |

`capacity()` allows live and historical work. Disk/database capacity is not the
observed blocker. Fetch-stage `capacity_deferred` also represents daily limits.
`daily_allowance()` counts the currently claimed running job, so the next article
after 300 completed fetch stages exceeds the count limit. Historical PDFs have
the same boundary after 25. Live PDF allowance is false because today's recorded
live bytes plus the PDF reserve exceed its daily byte allowance.

Pending work includes 947 article fetches waiting with `capacity_deferred`, 841
report fetches with the same error, and 79 queued report-extraction stages. There
are also 18 dead-letter report-index stages and two dead-letter discovery stages.
Those errors were not individually repaired in this check.

The scheduler wakes every 30 seconds but news discovery runs in **10:00, 14:00,
21:00 PKT** buckets. Announcements/report catalogs run in the 18:00 bucket.
Frequent dispatcher ticks do not mean fresh source polling every 30 seconds.
Daily allowance resets use UTC midnight (05:00 PKT); a budget reset is not proof
that all queued work will then complete.

## Comparison to the pasted design

Background discovery/fetch/parse/index, literal entity links, topic/sector tags,
statement extraction, conservative event objects, company sections, deterministic
query routing and compact packet assembly exist. Broad semantic event clustering,
active sentiment classification, routinely precomputed portfolio daily-impact
packets, and a consistently 1–4K-token query packet are not established by this
system. Portfolio quant is calculated/cached on demand; missing/stale company
sections can also be rebuilt during a query.
